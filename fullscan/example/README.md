## H297P 为什么值得停下来查

H297 落在 `HEYGHE`（297–302）里。这个片段看着像 HExxH ——金属肽酶的锌结合基序，果真如此的话 H297 就是配位催化组氨酸，而「催化残基上以 0.946 的概率换成脯氨酸」几乎必然意味着权重加载错了或者 token 差了一位。

查完三项，模型是对的：

| 检查 | 结果 |
| :--- | :--- |
| token 偏移 | 318 个位点全部对齐，0 处错位 |
| 未遮蔽复制任务 | 0.962 |
| 遮蔽野生型回收率 | **0.575**（天然蛋白常见 0.45–0.65） |

决定性的证据是同一次扫描里的另外两个位点：

| 位点 | p(wt) | 模型态度 |
| :--- | --: | :--- |
| S182（`GCSQGG` 中的 Ser） | 0.9990 | 几乎不允许替换 |
| H301 | 0.9997 | 几乎不允许替换 |
| H297 | 0.0014 | 偏好 Pro，概率 0.946 |

**同一个模型把 S182 和 H301 锁死，却完全不保守 H297。** 如果权重坏了，它不会有这种分辨力。所以 H297P 是模型的真实偏好。

## 我们第一次的解释是错的

最初我们把 `HEYGHE` 标注成 HExxH 金属肽酶基序、称 H297 是配位催化 His。数据不支持这个说法：真正被锁死的是 S182 和 H301，不是 H297。

结合 `GCSQGG`（GxSxG 亲核弯头）与 S182、H301 的高保守性，更一致的读法是 **Ser–Asp–His 催化三联体的 α/β 水解酶**：S182 为亲核丝氨酸，H301 为催化组氨酸，`HEYGHE` 与 HExxH 的相似属于巧合。H297 只是邻近残基。

这是纯序列层面的推断，**没有用到结构**。

这个教训直接改变了工具本身：`scan.py` 原来内置了基序模式匹配，现在删掉了，改为直接报告 p(wt) 最高的位点。测量值不会以这种方式出错，生物学解读留给了解该蛋白的人。
